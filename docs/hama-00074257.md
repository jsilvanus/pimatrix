# Hama Video Recording/Streaming Stick (00074257)

PiMatrix's Hama USB HDMI capture source targets the **Hama Video Recording/Streaming Stick, article number 00074257**.

## Vendor documentation

- [Official Hama product page](https://ae.hama.com/00074257/hama-video-recording-stick-usb-plug-hdmi-socket-4k)
- [Official Hama manual (PDF)](https://support.hama.com/webresources/article-documents/00074/man/00074257man_bg_cs_de_el_en_es_fi_fr_hu_it_nl_pl_pt_ro_ru_sk_sv_tr.pdf)

The vendor specifies:

| Property | Published specification |
|---|---|
| HDMI input resolution | Up to 4K / 30 fps |
| Capture/output resolution | Up to 1080p / 60 fps |
| Host connection | USB-A; USB-C adapter cable included |
| USB specification | USB 3.0 (USB 3.2 Gen 1) |
| Listed operating systems | Windows 11/10/8/7 and macOS (manual wording) |

These are vendor-level specifications, **not a list of Linux V4L2 modes**. The manual does not document Linux support, a chipset, USB VID/PID, supported V4L2 pixel formats, or frame intervals. PiMatrix must not assume that a particular mode such as MJPEG 1920×1080 at 30 fps is supported until the actual device is inspected.

## Discover the actual Linux capture mode

On the Raspberry Pi, install the inspection tools:

```sh
sudo apt update
sudo apt install v4l-utils
```

Connect the Hama stick, then list video devices:

```sh
v4l2-ctl --list-devices
```

Use the device node shown for the Hama stick in the next command (do not assume it is always `/dev/video0`):

```sh
v4l2-ctl --all -d /dev/videoN
v4l2-ctl --list-formats-ext -d /dev/videoN
```

Record the reported driver, card name, bus information, pixel formats, resolutions and frame intervals. Also inspect USB identity if necessary:

```sh
lsusb
```

## PiMatrix configuration

Capture is opt-in and remains disabled by default. Example base configuration:

```dotenv
PIMATRIX_HAMA_ENABLED=true
PIMATRIX_HAMA_DEVICE=/dev/videoN
PIMATRIX_HAMA_RTSP_URL=rtsp://127.0.0.1:8554/hama
```

Only set optional mode overrides after inspecting the device:

- `PIMATRIX_HAMA_INPUT_FORMAT`: exact format name accepted by FFmpeg/V4L2, such as `mjpeg` if reported.
- `PIMATRIX_HAMA_WIDTH` and `PIMATRIX_HAMA_HEIGHT`: set together to an enumerated resolution.
- `PIMATRIX_HAMA_FRAME_RATE`: use a reported frame rate.
- `PIMATRIX_HAMA_VIDEO_CODEC=copy`: only if the captured codec is compatible with the RTSP output.
- `PIMATRIX_HAMA_VIDEO_CODEC=libx264`: transcodes to H.264; confirm Pi CPU capacity at the selected resolution and rate.

When mode and codec overrides are omitted, PiMatrix leaves mode selection to FFmpeg/V4L2 and leaves output codec selection to FFmpeg. This is a discovery-safe starting point, **not a claim that the resulting stream is already validated**. Confirm with MediaMTX path readiness and a real preview before relying on it in production.

## Runtime design

- A single managed FFmpeg job owns the V4L2 device; don't open it separately for preview and output.
- FFmpeg publishes to MediaMTX over RTSP/TCP.
- MediaMTX provides the browser preview; PiMatrix does not proxy video.
- The capture job uses a local fffleet runner on the Pi. The USB device path is never submitted to a remote worker.
- Failed or unexpectedly ended jobs are retried with bounded exponential backoff.
- Physical device compatibility and actual supported modes must be verified on the target Raspberry Pi.
